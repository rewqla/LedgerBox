# README update checklist

Use this checklist after finishing any implementation step when the real project state has changed.

## Update README when

- New functionality has been implemented
- The local run flow changed
- The stack, infrastructure, or dependencies changed
- Architecture or feature boundaries were clarified
- New required environment variables appeared
- Owner-required actions changed
- New important constraints or caveats appeared

## Prioritize in README

- What is already implemented right now
- How to run or verify it locally
- Which architectural decisions currently matter
- Which configuration, secrets, or external services are required

## Avoid

- Describing future work as if it were already implemented
- Turning README into a changelog
- Copying the whole plan into README

## Quick review

- Does `Architecture` still match the real code structure?
- Does `Local run` still match the real startup flow?
- Does README reflect already implemented capabilities?
- Are all required env variables and external services mentioned?
